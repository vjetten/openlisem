Meteorological input

Meteorollogical data is given in a separate folder. Default name is 'rain'. The data is given per time interval which is indicated by "ddd:mmmm", Julian day number (1-366) followed by the minute in the day (0-1440) (note that 0 = 1440 = midnight). You can have two types of input, from stations (tipping buckets) and from images (satellite or rainfall radar). The format is as follows:

Rainfall data

Rainfall gauging stations.

  • Values are geven in mm/h and the timeinterval should be half-hourly or shorter. LISEM will work with larger time intervals (daily, weekly) but the results will be nonsense. Using raingauges needs a map ID.map with areas to which the raingauge corrersponds, using non-zero integer numbers (characters not allowed). If the map has 3 zones with numbers 1,5,17, these correspond to the columns in the input file, where column 0 is the time. Column 1 is area 1, column 3 is area 17 in this example. If you use in the header of the column a number this will be read as corresponding to the area in id.map. For this example (the word 'gauge' is optional, the number is read:

# A one line header, rainfall source
4
time
gauge 1
gauge 5
gauge 17
100:0230   20.0  4.3  17.2
100:0240   10.0  14.3  7.2
100:0251   11.2  8.3  87.2
etc

NOTE: the old rainfall file RUU format is no longer supported.

  • If you check "event based" rainfall, the day number is ignored and minutes can go from 0 to any number.
  • If you check "rainfall depth instead of intensities" it is assumed that the file has the time when tipping bucket tipped over. So the time interval is irregular and the values are in mm. In the model these values are recaclculated to intensity with the length of the time interval.
  • If you check "inverse distance interpolation", you have to add the x and y coordinates of the stations in the column titels: "gauge 1 123456.1 789700.5" All stations must be located in the map.   

Rainfall maps (pcraster format). Values are geven in mm or mm/h (check this) and the map format, size and resolution must be exactly the same as all other maps in the database. The map ID.map is not used. The source can be satellite or rainfall radar images or interpolated stations. The rainfall maps are stored in the rain folder and can have any name. The rainfall file looks like this:

# A one line header, rainfall source
2
time
maps
100:0180   rainfal.1.map
100:0210   rainfal.2.map
100:0240   rainfal.3.map
etc.

For both input types:

  • The option "Rainfall is recorded at the end of the time interval (def. on)" assumes that the gauge value(s) or maps next to a time represents the value at the end of the interval. This is normally the case so by default this option is checked. A gauge counts the number of tips at the end of an interval, and images usually give the rainfall depth (or intensity) at the end of the interval. In previous versions it was assumed that the rainfall is at the beginning of the timeinterval, so for backward comp[atibility you can unckeck this option. 

 

Evapotranspiration data

The format of the input files is exactly the same as for rainfall, either station data with a map (ETID.map) or a series of ETp maps are used.

If the timeinterval is less than 1 day (e.g. hourly),  the values are assumed to be in mm per timeintervall. Please make sure that the nighttime ET is zero.

If the interval is 1 day or more, the values are assumed to be in mm/day. In that case select the option "ET has daily or larger timesteps", and supply the average latitude (in degrees, e.g. 22.5) of the area. This will be used to calculate the sun engle and day length. The ETp provided in mm/d (in the gauges or maps files) is assumed to represent the daylight period and the instantaneous ETp per timestep is calculated according to a sine curve between sunrise and sunset.

If the time interval is longer than a day (e.g. derived MODIS 8 daily values), you still have to provide average daily ETp in mm/day, and the daily ETp is simply repeated for the 8 days until the next timestep is found in the input file.
