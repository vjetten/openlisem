Channel and Groundwater options

Channel

IMPORTANT:

  • Channel flow is done with a kinematic wave, which sensitive to dt and dx. It is advised to use a dt (in sec) that has the same size or smaller than the cell size (in m). Calibration on one combination of dt and dx is not applicable to another dt and dx.
  • The channel width can be larger than the cell size. In that case the velocity and discharge are calculated with the user defined (true) dimensions. However, for overland flow to flow into the channel, or water to flow out of the channel, the width is temporarily made smaller than the gridsize (0.9 dx) and deeper, to maintain mass balance. 

Overland flow flows into or out of the channel using broad weir hydraulics. The flow into or out of the channel is calculated as:

Q = 2*dx*Cd*sqrt(2g)*(h1+vf-h2)1.5

where (h1-h2) is the difference between the channel water height above the edge and the overland flow water height, whichever is larger. The factor vf is the velocity factor in case h1 is the overland flow based on the overland flow velocity (V): vf = V2/2g. In case h1 is outflow from the channel, vf is zero.

The channel cross section can have different shapes, determined by the channel side slope angle (chanside.map). This is the tangent of the angle with the vertical: 0 is rectangular, 1 is 45 degrees etc.

NOTE: the channel side should be the TANGENT with the vertical: value 0 = rectangular, value 1 = 45 degree angle.

  1. Rectangular: the chanside.map is zero
  2. Circular: channel diamater is given (mm) , chandiameter.map. The channel is assumed to be a pipe, with confined flow when full. Circular is only used for culverts.
  3. Trapezium: channel side has a value, the channel width is the top with at the surface (chanwidt.map). The bottom width is calculated internally, using the side angle and the depth (chandepth.map).
  4. Triangular: The channel side map is non-zero, and has a value that, together with the depth, causes the bottom width to be zero. 

Culverts: culverts are parts of the channel that can become confined flow, where the kinematic wave reaches a maximum flow. .can have one of the four shapes above (ususally circular). This is specified in the map chanculvert.map (values 1,2,3,4 for rectangular to triangular). It is the responsibility of the user to supply a correct manning's n inside the culvert part (e.g. 0.012 for a concrete pipe). The slope is the user defined slope (changrad.map). If a value 2 is given, the chandiameter.map is used, if 1,3 or 4 are given the channel width, depth and side are used. 

NOTE: culverts do not receive rainfall or overland flow, and they do not infiltrate nor receive groundwater.

NOTE: To calculate confined flow with a kinematic wave (flow in culverts that have a maximum when they are full), openLISEM can make use of a userdefined maximum discharge with the map chanmaxq.map (in m3/s). Where this map has value 0 (zero), the maximum discharge is calculated with the culvert shape dimensions, slope and manning's n.

Stationary baseflow: the stationary baseflow is added every timestep in the run, for all cells in the channel. The value of each channel cell is determined from the desired baseflow at the outlet of a channel. This value is supplied by the user in a map baseflow.map (def. name). For insatnce, if the outflow point of the channel has a stationary baseflow of 5 m3/s, all channel cells will receive a value that results in 5 m3/s at the outlet when using a kinematic wave (using the channel Manning's n and gradient).

Channel infiltration: a value is subtracted from the discarge based on the Ksat value in chanksat.map (in mm/h). This is mutually exclusive from baseflow.

Channel tortuosity: in LISEM channels are assumed to be rectangular. If the perimeter is large that the rectangular perimeter, a factor > 1 can be used.

User defined inflow: at certain locations defined in Qinpoints.map (values 0,1,2,3...) a user defined inflow in m3/s is added to the river discharge. These points must be in the channel. Each point has a column in the user discharge file. This files has the same format as the rainfall:

# A one line header

Groundwater and baseflow

Groundwater is in the soil profile as a saturated layer. The groundwater can rise in the soil profile because of percolation downward and it lowers because of lateral flow.

IMPORTANT:

  • Groundwater is assumed to build up during the run, these calculation are not meant for deep/thick groundwater layers, such ass done with e.g. Modflow.
  • Stationary baseflow is independent of the groundwater (for now).
  • Groundwater flows over the "bedrrock": it assumed that the bottom of the soil profile (DEM - soil depth) is the layer over which the groundwater flows. This means that the total soil depth is important.

Grounwater can be simulated using 3 options:

1. Pressure based flow, in a 3x3 window using total hydraulic potential (gravity + pressure). No iteration is done so this can become unstable. Used in detailed simulations of smaller areas.

2. Flow along a predined user network (lddgroundwater.map). the flow is pressure based but flows in the direction of the LDD. For larger scale modelling, results do not look like a smooth water table, but the method ignores local depressions in which gorundwater gets stuck.

3. groundwater is treated following principles of the model SWAT (2009).Water does not flow towards the river but form every cell some groundwater is taken and added to the river, where the amount is smaller as the cell is further away. For large scale modelling. Two additional maps are needed: a map that gives the distance to the channel (basedistance.map), and a LDD map giving the flow direction towards the channel (lddgroundwater.map). 

To influence the groundwater 4 parameters can be set, all are relative calibration parameters:

- Recharge of the groundwater from the soil profile (vertical flow), based on the unsaturated Ksat and soil moisture content, multiplication factor (0-100, def 1.0)

- Groundwater flow towards the channel cells (lateral flow), based on Ksat, porosity and inverse distance to the channel: multiplication factor (0-100, def 1.0)

 - A percolation loss factor of groundwater to deeper layers, in mm/h
